# 游迹

个人使用的 Windows 游戏与影视资料库，基于 Tauri 2、Rust、Vite 和 SQLite。游戏支持 Steam 账号导入、本地 `.exe`、官方及本地成就；影视支持媒体目录扫描、TMDB 资料、豆瓣观影记录与播放器进度。

## 托盘菜单

单击托盘图标打开主窗口；右键显示「最近游戏」「最近影视」，各最多 5 项，条目仅显示名称，影视按电影或季合并。点击游戏正常启动，点击影视从最近有效分集和文件续播并加载完整播放列表；失败打开主窗口提示。「退出」位于末尾。

弹出菜单共用主界面的亮暗主题、主题色和字体，从鼠标落点展开，靠近屏幕边缘时向内避让，记录变化时同步调整尺寸与位置。圆角外透明；方向键、Home／End、Enter 可操作，Escape、外部点击或失焦关闭。暂无独立作品图标时不额外下载。

## 好友动态与个人空间

登录同一游迹云服务后，可从侧栏“好友”复制自己的好友码，发送申请并由对方接受。成为好友后默认可以互看昵称、头像、简介、正在玩、最近游玩、游戏库、时长和成就；不会公开邮箱、平台账号标识、本机路径或存档。个人空间使用已同步资料，未同步时请先完成原有云资料导入。

“我的空间 → 编辑资料与隐私”可设置隐身、游戏库／时长／成就可见性和隐藏指定游戏。隐身不隐藏个人空间；隐藏游戏同时从动态、最近游玩和统计中移除。头像支持内置图案与不超过 500 KB 的 PNG/JPEG/WebP，自定义图片由服务端重新编码。已同步游戏的本机封面会在后台上传供好友查看（包含自定义封面），内容相同不重复上传；只传图片内容，不传本机路径。单图源文件上限 8 MB，服务端去除元数据并压缩到最大 600×900。成就图标使用已同步的平台 HTTPS 地址；未解锁隐藏成就不暴露图标。空间支持全屏，游戏详情按多列图文展示。

游迹运行或驻留托盘时，每 30 秒报告在线状态，每 5 秒读取好友动态；断线超过 90 秒显示离线。只播报实际检测到的游戏运行，首次登录、重连及免打扰期间不会补发旧通知。好友弹层默认右下角无声显示 5 秒、不抢焦点、鼠标穿透，成就提示优先；独占全屏不保证显示。好友列表支持静音、删除和屏蔽。首版不提供聊天、评论、公开网页或 Steam 外部好友。

服务端需要先应用 `0006_social.sql`、`0007_social_covers.sql` 再更新客户端；头像与游戏封面分别使用私有对象的 `social/avatars/`、`social/covers/` 子前缀。封面读取检查当前好友关系、游戏是否存在及可见性，隐藏游戏或删除好友立即阻止后续读取，不与存档清理混用。

## 影视库

窄竖栏顶部为游迹入口和「游戏／影视」图标按钮，右侧菜单显示当前资料库内容，两种模式共用竖栏底部的设置图标。影视数据保存在独立 `media.sqlite`，暂不参与游戏云同步或应用数据备份与恢复；恢复游戏 v3 备份保留现有影视数据。不迁移开发版影视库，也不读取开发期 v4 影视备份。

### 添加、浏览与搜索

「添加目录」扫描本地媒体；「添加影视剧」搜索 TMDB，选择电影或具体季后添加无资源条目，已收录身份直接打开并保留个人记录。资料获取失败不会留下空条目。

片库按电影、具体季展示，整剧用于组织各季。分类包含最近添加、最近观看、收藏、已看／未看、未识别和本地目录；已观看、已识别、可观看筛选可以组合，分类固定的维度不再重复筛选。未识别状态区分待识别、未匹配、识别失败。题材缺失时回退所属剧，明确单季剧的第一季可省略季名。

电视剧详情在同页切换季集及资源版本，保存 TMDB 返回的完整集目；离线或无资源分集仍可查看和记录观影，播放不可用。「仅看有资源」包含关联但离线的文件。季与单集的已看、评分、短评、收藏分别记录，标记本季已看不生成逐集观看记录。详情刷新及返回保留当前季集、版本、展开区域、滚动和焦点。

「全部影视」「最近添加」展示作品横幅，「最近观看」展示继续观看；其他分类以作品列表为主。详情展示剧照、可用的中文艺术字、演职员及「我的观影」，缺图回退标题。演员横排最多 12 位主演与少量主创，电视剧标注本季范围；附加资料异步加载，失败可用旧缓存。鼠标、键盘聚焦或触控可直接播放。

顶部搜索覆盖整个影视库的作品、人员姓名及已收录别名，不继承当前分类筛选；本地目录搜索限当前目录，并匹配原始文件／目录名。输入后按 Enter 或搜索按钮执行，作品与演职员各每页 30 项，可跳页；搜索页暂停自动整库刷新，资料变化后点击「刷新结果」。点击人员可筛选库内作品，同名不同 TMDB 身份分别展示；完整人员索引由后台补齐，不受详情横排人数限制。

搜索、人员作品、本地目录及详情共用逐级返回记录，恢复搜索词、筛选、页码、位置和焦点；点击侧栏结束临时浏览路径。大列表分块渲染，后台只更新变化区域，播放进度局部更新。

### 媒体目录、扫描与忽略

「本地影视」保留实际目录层级；智能文件夹只将明确属于单部电影、某剧或某季的目录折叠为作品卡片，混合目录保持文件夹。季／集标题补全剧名，Windows 扩展路径前缀只在显示时隐藏。同目录刷新保留搜索草稿与位置；目录离线或读取失败提供重试。扫描不改名、移动或删除媒体文件。

游迹运行或驻留托盘时监听源目录及子目录变化，静默 2 秒或持续变化 10 秒后启动完整扫描，扫描中发生的变化去重补扫。默认每 30 分钟定时兜底；自动扫描设为 0 同时关闭监听。入库先刷新列表，技术探测随后完成，仅新条目进入自动识别，旧失败保留退避。实际耗时取决于目录规模、磁盘及网络共享支持。

资源版本按文件大小和修改时间判断。不变文件不重复更新；版本改变时重置该资源的进度、覆盖与技术参数，保留作品记录和历史会话，旧播放会话不能写回新版本。同大小且同修改时间的替换无法检测。`._` 伴随文件不收录，TS／ISO／IMG 须通过视频结构检查，镜像只作受限只读检查、不挂载；明确 sample、预告等附加片不自动当正片识别，正常短片不因时长短而排除。

文件／目录可通过右键、悬停或键盘操作「忽略」，在「忽略列表」或设置中「忽略项」取消并扫描；离线时也可取消规则。磁盘目录可放置空 `.youji-ignore` 文件来排除整棵子树，源根目录同样支持，标记由文件管理器管理，不出现在应用内规则列表。两种规则均阻止旧扫描、探测和识别任务重新写回。

移除来源、确认丢失或忽略共用清理规则：有其他资源、独立收录、个人记录、收藏夹／标签、历史或进度支撑者保留；无支撑的本地条目、季集树与空父剧删除。历史引用保留但不可播放；仅有 TMDB 资料不构成保留条件。目录临时离线或扫描不完整不会清理未经确认的丢失资源。重新添加或取消忽略后可重扫恢复，正在播放相关文件时须先停止。

### 识别、豆瓣导入与资料更正

「设置 → 影视库」配置媒体目录、TMDB API Key／Read Access Token、播放器及可选 ffprobe／ffmpeg，查看扫描与导入任务。凭据保存于 Windows 凭据管理器并按应用数据目录隔离，不写 SQLite 或回传界面。配置页独立读取设置与任务，刷新保留未保存输入。

本地自动识别精确核对 TMDB 正式名、原名、别名、电影／季年份及实际季集，支持常见 `S01E01`、`E01/EP01`、`[01]`、`#01` 和中文集号。明确季号可使用整剧首播年或该季年份；缺季号须唯一确定。双语名称可相互佐证，多季合集、同名同年或证据冲突保留未识别，不按热度选第一项。无匹配／歧义等待线索变化或手动处理；临时网络错误按 15 分钟、1 小时、6 小时、24 小时退避，之后每天重试。

登录隔离的豆瓣官方窗口后，后台导入本人「看过」的新增作品、星级、日期、标签和短评；已有豆瓣编号整条跳过，不追随后续修改、取消已看或账号切换改写个人记录。首次读取全部历史，之后从最新记录读到上次成功轮次的首条编号；按账号保存边界，仅整轮成功才前移。中断保留已导入数据，下次从头去重；边界已删除时可能读到末页。断开连接清除登录会话并停止更新，保留条目与边界；登录过期或验证须本人处理。

新增条目自动获取 TMDB 资料，电影对应电影、剧集对应具体季。无可靠候选或有歧义时按需读取豆瓣详情，缓存 IMDb、类型和季号辅助匹配；已有 IMDb 线索优先查询。季年份能唯一对应时允许两站季号不同；OVA 对应 TMDB 单集时只迁移该集记录，分段／合并季范围冲突保留待确认。豆瓣标记不补算播放时长，也不展开成整剧／逐集已看。

手动识别搜索并选择电影或具体季，识别／刷新季时复用完整集目及原记录。同一作品更新用「刷新资料」；跨作品或跨季更正校验原子树身份，不把旧分集带入另一季。库内合并只允许未识别来源归入已识别目标，冲突来源身份拒绝合并；个人记录按本地人工、本地、豆瓣来源优先级补齐，已有非空同级记录保留目标。

TMDB 缺少的独立电影或季可在「识别／更正资料 → TMDB 没有这部作品？ → 从豆瓣获取资料」填写豆瓣链接／编号，预览标题、年份、完整简介、海报、类型和 IMDb 后确认。无需先导入看过记录；页面验证或窗口忙碌时可重试，预览失败不改条目。确认原地保存并标为已识别，保留个人记录、文件关联与进度；豆瓣剧只保存季级资料，不生成整剧或占位集。可通过「更新豆瓣资料」补齐旧简介／封面，或「解除识别」保留来源身份；不自动覆盖已有 TMDB 身份、不同豆瓣编号或父子层级。详情作品链接可打开对应豆瓣、TMDB、IMDb 页面。

### 单季匹配与条目清理

单季目录的右键或工具栏「匹配／更正本季剧集」先选择电视剧与季，再预览已扫描文件的原关联和目标集号。默认只含当前目录，可包含子目录；支持集号偏移、手工填写、跳过、多版本与 `1-2`／`1,2` 合并文件。季号冲突默认不建议，需明确允许后重新建议，不读取视频内容猜集号或移动文件。

「预览更正影响」列出记录迁移与冲突：无其他文件的旧条目可迁移个人记录、整理及观看历史，保留文件级进度与覆盖；仍有范围外文件或显式保留记录者不清理。目标不同评分／短评／日期须逐项选择，旧 TMDB 身份与分集树不搬运，来源冲突不静默合并。确认后统一事务提交；文件、关联或记录变化需重新预览，播放期间拒绝执行。

无关联资源的错误条目可从右键或详情「清理条目」预览删除所选条目、子项及无支撑空父级。有个人、豆瓣、观看记录或整理归属时须明确勾选删除；任何关联资源（含离线／忽略资源）都会阻止清理。只删除确认的库内数据，不改磁盘文件、文件级进度或共享收藏夹／标签定义。预览变化需重做，播放期间拒绝，清理后无法直接撤销；重新导入来源可能再次收录。

### 播放、续播与观影记录

支持 PotPlayer 与 mpv，可自动查找或指定路径；只跟踪游迹启动的独立实例，核对实际文件身份后保存位置和有效时长。暂停、跳转、缓冲与休眠不按进程存活时间计时。进度达已知总时长 95% 自动标记已看，快进同样生效；实际覆盖如实记录，不参与完成判定。同会话只自动标记一次，用户取消已看不会被重复覆盖。已看与续播独立，不套用其他剪辑版本的位置。

电视剧默认加载全剧各季及特别篇的可播放文件，按季集排序，跳过离线、缺失与忽略文件。每集优先最近播放的有效版本，否则按路径选择；当前集保留明确选择，同路径合并文件去重。mpv 与 PotPlayer 均加载完整前后列表并定位所选文件，PotPlayer 使用会话结束后清理的临时 DPL。切集分别保存会话与进度，不自动判上一集已看；未收录文件暂停记录。

PotPlayer 命令行续播先检查实际落点，5 秒容差内不重复跳转，偏差大时有限补跳，加载零位置不覆盖旧进度。读取间隔默认 500 毫秒，可设 50–2000 毫秒整数，下次播放生效。mpv 通过事件同步位置与状态，不受轮询间隔影响；普通检查点约两秒保存，暂停、跳转、切集和退出立即保存。悬浮状态条可定位正在播放或停止，不改变正在浏览的季集／版本；播放完成退出续看区，重播从头开始，仅手动／豆瓣已看不清除续播。

「观看记录」按日期、来源及类型查看已看数、记录天数、平均评分、有效时长、日历、分布及播放明细；日历按本机时区汇总标记与真实播放，同一作品多日观看可分别查看。已看操作补空日期为当天，原日期及人工评分／短评受保护，豆瓣明确无日期保持未知。

### 技术信息、图片与开发参考

ffprobe 读取容器、分辨率、码率、音视频轨和字幕，未知值不猜测。ffprobe／ffmpeg 可分别指定路径；留空时按另一工具同目录、PATH、常见安装目录查找，显式路径无效不静默回退。

缺图的未识别普通视频在图片进入加载范围后按需抽帧，已有图片优先，识别成功改用资料图，解除识别保留资料图。列表与详情按有效视频路径稳定选源，已有缓存直接读，封面与背景共用请求；前端最多两请求、后端串行，离屏未启动请求跳过。抽帧最多 35 秒，图像不超过 1280×720，失败退避 15 分钟；ISO／IMG／原始 YUV 暂不自动截图。缓存随文件版本失效，512 MiB 预算只回收可重建截图；未识别且缺背景时详情另有无遮罩截图区。

浏览器预览使用公开 TMDB 资料与明确示例资源，不读本机凭据或启动播放器。后端与前端契约、缓存上限、诊断日志及回归入口见 [影视协作接口](src-tauri/src/media/CONTRACT.md)；术语见 [资料库领域](CONTEXT.md)。

## 自动识别存档目录

在游戏详情的“游戏存档 → 识别 / 绑定存档目录”中，自动检查内置规则指向的目录，展示候选路径、文件数、大小、最近修改时间及匹配依据。点击“使用此目录”只填入路径，仍需“确认绑定与设置”；未找到时可直接手动选择。已有绑定目录不会重复列出。

规则来自 [Ludusavi Manifest](https://github.com/mtkennerly/ludusavi-manifest) 的保守 Windows 子集，离线可用。Steam 游戏和填写过 Steam AppID 的本地游戏按 ID 匹配，其他条目按准确名称匹配；多个账号分别展示，不自动选取。不会全盘扫描、读取存档内容或自动上传。恢复会替换整个绑定目录，确认时应核对目录只属于当前游戏。规则未覆盖、名称不一致、目录尚未生成或不安全时仍需手动定位。数据来源、许可证与更新方式见 [规则说明](src-tauri/data/README.md)。

## 运行

Windows 开发环境需要 Rust、Microsoft C++ Build Tools、WebView2 和 Node.js。安装依赖后：

```powershell
npm install
npm run tauri dev
```

打包 Windows 安装程序：

```powershell
npm run tauri build
```

安装包输出在 `src-tauri/target/release/bundle/`。Windows 是目标平台；浏览器预览用于界面开发，播放器进度对接需运行 Windows 桌面端。

仓库根目录的 [Windows Release 工作流](../../.github/workflows/windows-build.yml) 在版本配置变更推送或合并到 `main` 时，比较此次推送前后的应用版本。版本号变化并通过一致性校验后，才使用 GitHub 托管的 Windows 环境构建 x64 NSIS 安装包。版本号不变时跳过构建；PR、功能分支和单独推送标签不会触发发布。

- 构建成功后自动创建 `v版本号` 标签并公开发布 Release，上传 `.exe`、更新签名和 `latest.json`，使用对应版本的中文发布说明。无需手动推送标签或确认草稿；包含 `-` 的版本标签标记为预发布。
- 上传前将安装包文件名统一为 `youji_版本_x64-setup.exe`，避免 GitHub 移除中文文件名中的应用名称；应用名称仍为“游迹”。
- 同时上传 `youji-windows-x64` Actions 产物，保留 14 天，可从工作流运行页面下载。
- 构建任务只需读取仓库；Release 任务使用 GitHub 自动提供的 `GITHUB_TOKEN` 写权限，无需额外配置个人 Token。

发布前统一 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 和 `src-tauri/tauri.conf.json` 的版本，再提交并合入 `main`。例如将版本从 `0.2.2` 升到 `0.2.3`，合入后会自动构建并创建 `v0.2.3` Release。

任一版本配置不一致时会在构建前失败。如果同名版本标签已指向其他提交，必须使用新版本号，工作流不会移动已有标签。构建使用 `npm ci` 和 Cargo `--locked`，依赖锁文件必须已提交。`src-tauri/resources/XboxLocalProbe.exe` 等打包资源也需要在仓库中；工作流只上传生成的安装包。

Release 说明来自 `release-notes/<版本号>.md`。发布前必须配置更新签名 Secrets；工作流先对安装包和签名执行密码学及版本校验，再上传草稿，产物完整后公开发布。同一标签的草稿可重试，正文以仓库中的说明为准；已发布的 Release 会跳过，不会覆盖。构建失败或取消后，可在原 Actions 运行页面重新运行；版本判断仍使用原推送前后的提交。标签创建、构建与发布由同一个工作流完成，不依赖自动创建标签再次触发 Actions，也不需要额外配置个人 Token。

## 首次使用

1. 在“设置”中填入 [Steam Web API Key](https://steamcommunity.com/dev/apikey) 与 SteamID64。账号游戏详情需可见，游戏库和官方解锁状态才能通过接口读取。
2. 点击“从 Steam 账号导入”。程序调用官方 `IPlayerService/GetOwnedGames/v1` 导入账号拥有的游戏，包含未安装游戏；重复导入不会覆盖已缓存的资料和成就。游戏库立即显示可用的 Steam 竖版封面，后台逐款获取简体中文商店名称和简介；没有中文名称的游戏保留 Steam 返回的原名。已有游戏也会在启动时补全资料。
3. 点击“添加本地游戏”选择 `.exe`，填写对应 Steam AppID。详情页的“更新资料与成就”会尝试从 Steam 获取游戏资料与成就定义。
   名称搜索使用 Steam 官方 `IStoreQueryService/SearchSuggestions/v1`，游戏资料使用 `IStoreBrowseService/GetItems/v1`。优先查询中国区，没有有效候选或资料不可用时自动查询美区，均使用简体中文。竖版封面和横幅按接口返回的资源清单、语言路径及地址模板获取并缓存。桌面端缓存下载在现有图片候选缺失或全部失败后，核对中区、美区对当前 AppID 的返回状态；只有双区都返回 `success: 15`（访问被拒绝）才尝试官方 CDN 高清、普通版及 header 图片，每次获取只追加一次，复用原下载和本地缓存机制，不写入额外资料标记。已有缓存直接读取，主动更新失败保留旧图。网络错误、无效响应、空结果、其他错误码或游戏身份不匹配均不会触发 CDN 兜底；资料获取失败保留已有资料。已有 Steam 游戏与关联 Steam 资料的本地游戏会在启动时补齐。
   也可将游戏 `.exe` 或指向 `.exe` 的 Windows `.lnk` 快捷方式拖入主窗口，自动填写程序路径与名称，预填名称后等待 400 毫秒自动搜索 Steam 候选，选择对应游戏后再确认添加。每次支持一个文件，重复程序会提示；拖入本身不会启动游戏或直接保存。快捷方式只用于解析目标 EXE，以程序所在目录为工作目录，不保留快捷方式的启动参数和工作目录，也不依赖原快捷方式。拖入导入与常规导入一样，默认不勾选跳过 Steam 资料关联，选择对应游戏后关联资料与成就，也可按需勾选跳过；不支持 `.url`、文件夹或无法访问目标的快捷方式。

   添加和编辑本地游戏时，「游戏程序」始终选择实际运行的游戏 EXE，用于平台识别、运行检测和时长统计。需要官方启动器的游戏可开启「通过启动器启动」，另选「启动器程序」；关闭则直接运行游戏程序。两个路径框都可通过选择文件或拖入 `.exe`／`.lnk` 填写，快捷方式解析后保存目标 EXE。拖入弹窗中的路径框只更新对应路径，不另建游戏或覆盖名称和资料关联；无弹窗时继续按原流程导入。不能将同一 EXE 同时设置为游戏和启动器，但多款游戏可使用同一个启动器。
4. 本地游戏默认检查 `%APPDATA%\GSE Saves\<AppID>\achievements.json`、`%APPDATA%\Goldberg SteamEmu Saves\<AppID>\achievements.json`，以及 `%PUBLIC%\Documents\Steam\RUNE\<AppID>\achievements.ini`、`CODEX` 的同类目录。其他位置可在游戏详情页“编辑”中指定 JSON 或 INI 的完整路径。本地配置编号与已确认的资料 AppID 不同，可以用配置编号查找记录，但解锁标识必须与当前游戏定义匹配；不修改游戏配置。
5. 若游戏目录下存在 `steam_settings\achievements.json`，它可作为成就定义的本地来源。这个文件通常是**定义数组**；实际解锁记录是保存目录中的**对象**，两者不能混用。

后台每 3 秒检查本地记录。启动时导入已有解锁且不弹历史通知；新解锁会写入本机数据库并弹系统通知。Steam 官方成就每 30 分钟尝试同步一次，也可在详情页手动更新。网络失败时，已缓存的资料和成就仍可查看。

Steam 成就定义优先通过官方 `IPlayerService/GetGameAchievements/v1` 获取简体中文名称、完整说明（含隐藏成就）和图标，无需 API Key 或登录；该接口失败时，有 API Key 才回退到原定义接口。响应缺少有效列表不视为“暂无成就”，空名称、说明或图标不覆盖已有完整资料。Steam 账号解锁状态继续使用 API Key 与 SteamID64 同步，本地游戏仍读取受支持的真实解锁记录。

游戏详情沿用直接显示成就名称、图标和说明的方式，未解锁的隐藏成就也展示已获取的资料，不增加遮蔽、点击揭示或相关配置。隐藏成就的描述缺失时仍显示「隐藏成就」；点击「更新资料」可通过新官方接口补全说明。

## 范围与数据

- 只读取 Steam 官方接口、游戏程序和本地成就记录；不会修改游戏文件或运行环境。
- 本地游戏自动解锁需要运行环境写出受支持的记录。没有记录时，详情页会显示“未找到解锁记录文件”，并允许手动记录成就。
- 本地游戏要求管理员权限时，启动器会在 Windows 返回“需要提升权限”后弹出系统 UAC 确认，授权后启动并继续跟踪进程。取消授权会提示游戏未启动，可以重新尝试；启动器本身无需以管理员身份运行。
- RUNE／CODEX INI 仅以对应成就分区的 `Achieved=1` 判定解锁，读取 `UnlockTime`，忽略 `SteamAchievements` 索引和进度数字；必须先获取对应游戏的成就定义，避免串入其他游戏记录。
- 当前自动读取器支持 GSE／Goldberg JSON 的 `earned`／`earned_time`，也接受兼容字段 `Achieved`／`UnlockTime`。对于 AppID `1123050` 的 GRIME，还会在没有运行环境记录文件时只读扫描 `%USERPROFILE%\AppData\LocalLow\Clover Bite\GRIME\Save Files` 中的 `.gd` 存档，通过已缓存的 Steam 成就定义验证解锁标识。存档只有解锁标识，没有可靠的解锁时间；历史解锁以首次导入时间记录。其他不产生记录文件的游戏仍需要专属规则或手动记录。
- 数据库位于系统应用数据目录的 `dev.local.achievementlauncher/games.sqlite`。Steam Web API Key 也保存在该本机数据库中；请保护当前 Windows 用户账户与该文件。

桌面端将竖版封面和横幅分别保存到应用缓存目录的 `covers/`，缓存索引保存在现有 SQLite 设置表中，不需要修改数据库结构。首次显示时下载缺失图片；缓存存在时直接读取本地文件，返回主页和重新启动不会再次下载。只有详情页「更新资料」会在后台刷新已有封面，定时成就同步不刷新图片；下载失败保留旧图，内容相同保留原文件，内容变化后使用新文件地址避免 WebView 继续显示旧图。重新关联另一款游戏后不会使用原关联的封面。普通浏览器预览继续使用原图片地址。

Steam、Epic 和本地关联游戏均使用上述缓存。Epic 导入时从官方 `keyImages` 分别保存竖版与横版候选，跳过空地址并保留备用图片；手动「更新资料」先刷新该游戏的 Epic 商店图片地址，再独立同步成就和刷新封面文件。商店资料读取失败保留旧资料，不影响继续尝试成就同步，也不清空原封面。

编辑本地游戏时，已关联的 Steam 资料缩略图复用游戏库的横版封面读取与本地缓存逻辑，缺失时沿用已有下载和图片回退；重新搜索与选择新游戏仍使用搜索接口返回的候选图片。

缓存下载共用已有图片网络客户端和代理配置，最多四个并发，同一游戏、同一封面类型的请求串行合并。仅接受 HTTP／HTTPS 图片候选，并限制单张图片最多 20 MB，检查 PNG／JPEG／GIF／WebP／AVIF 文件头后才保存；完整文件写入成功后才切换索引。本地图片协议只开放应用缓存目录的 `covers/` 文件。

缺少封面时使用跟随主题的底纹、游戏图标与名称占位；真实图片解码完成后以渐显、轻微缩放与清晰化过渡替换占位，已加载的复用图片直接显示。鼠标悬停或键盘聚焦时，封面扫过一次斜向高光，并配合轻微缩放和边缘高亮；减少动态效果偏好会关闭扫光与模糊过渡。

## 收藏、最近游玩与运行检测

- 点击封面右上角的星标收藏游戏；收藏游戏在名称排序时置顶，也可通过侧栏「我的收藏」集中查看。详情页和大屏模式支持收藏操作。
- 「最近游玩」按实际确认的游戏启动时间倒序排列。详情页显示最近游玩时间和本机累计时长；通过启动器启动并检测到实际进程后才开始记录，不会把发送 Steam 启动请求视作成功运行。
- 启动按钮显示「正在启动」或「游戏运行中」，同一游戏运行期间禁止重复启动。进程退出后恢复启动按钮，并检查本地成就记录。时长每 30 秒及结束时保存，重复保存不会重复累计。
- 本地启动器模式打开启动器后显示「等待游戏启动」，持续等待指定的实际游戏进程，不沿用普通启动的 90 秒超时。只有实际游戏运行才计时并按设置最小化游迹；游戏退出后结束计时，启动器及其更新、登录或常驻进程不计入。普通详情、推荐区与大屏提供「取消等待」，只停止此次等待，不关闭启动器或游戏；检测到实际游戏后不能取消等待。进程恢复同样只核对实际游戏。
- Steam 游戏通过进程的 Steam AppID 标记确认运行。无法确认时，90 秒后提示「未确认游戏进程」；可在详情页「启动检测设置」选择真实游戏程序辅助检测。这个路径仅用于检测，游戏仍通过 Steam 启动。
- 设置中的「确认游戏运行后最小化，结束后恢复启动器」默认关闭；开启后只在确认进程时自动最小化，全部受跟踪游戏退出后恢复自动最小化的窗口。
- 游玩时长统计仅覆盖启动器当前运行期间跟踪到的进程，不是 Steam 账号的历史总时长。收藏和历史游玩记录保存在本机 SQLite 数据库。

## 成就检测引导

添加本地游戏后自动打开引导，也可从详情页「成就检测引导」进入。引导展示 AppID、定义来源、实际检查的记录路径、文件是否存在、上次读取时间和解锁数量，支持重新检查、指定 JSON 文件、恢复自动查找以及补全定义。

引导区分缺少 AppID、缺少完整定义、记录缺失、读取失败与检测就绪。只有已解锁条目的部分定义不会被显示成完整成就的 100%。重新指定记录路径时，已有记录作为历史导入，不补弹通知；游玩中新产生的解锁才弹通知。成就名称和图标本身不能触发解锁。

自动化测试还覆盖收藏持久化、游玩时长重复写入、真实子进程运行与退出、重复启动保护、检测状态以及最近游玩／收藏筛选。Windows 掌机上的真实 Steam 游戏进程识别与窗口最小化／恢复仍需实机验证。

## Steam 本机安装状态

账号拥有的游戏仍由官方 Web API Key 导入。本机安装检测独立运行：Windows 上通过 `steamlocate` 定位 Steam 和各游戏库，读取 `libraryfolders.vdf`、游戏 `appmanifest_*.acf`，检查安装完成标记和实际目录。只读检查，不修改 Steam 文件，不自动安装游戏。

- 已安装：显示「开始游戏」；尚未安装或安装未完成：显示「安装游戏」，点击打开 Steam 的安装界面，由客户端确认安装、继续下载或修复。
- Steam 客户端缺失：显示「Steam 未安装」；首次检查尚未结束：显示「检查安装中」。
- 清单损坏、读取权限不足或游戏库磁盘无法访问：显示「无法确认安装」并禁用，附带原因；不会将检测失败当成未安装。其他不可访问库不会影响已经在可访问库中确认安装的游戏。
- 启动时检查，后台每 5 秒刷新；安装状态仅保存在内存，只有状态或原因变化时发送界面更新。检查时间变化不会反复重绘。
- 普通游戏库推荐区、详情页和大屏模式使用同一按钮逻辑；已经跟踪的启动中／运行中状态优先显示并继续禁止重复启动。
- 点击启动时，后端重新读取安装状态。游戏已卸载时立即拒绝启动，不发送 Steam URI，也不创建运行会话。游戏的收藏、资料和成就仍可查看。

### 平台游戏安装入口

详情页、普通游戏库推荐区和大屏推荐区统一使用「安装游戏」文案。Steam 未安装时主按钮直接提供安装入口，调用 `steam://install/<AppID>`；安装完成后现有每 5 秒检测自动切回「开始游戏」。有效家庭共享游戏使用同一流程，已失效的共享条目继续禁用；Steam 客户端缺失、状态尚未确认或检测失败时不提供可用安装操作。点击时后端重新检查，缓存已过期且实际已安装时刷新界面并提示使用「开始游戏」。

Epic 保留「在 Epic 中打开」，旁边另加「安装游戏」，以已导入的 Epic AppName 构造 `com.epicgames.launcher://apps/<AppName>?action=install`。本轮不增加 Epic 本机安装检测，不据此判断已安装、未安装或安装完成；已安装游戏的安装请求如何处理由 Epic 客户端决定。

安装入口仅在 Windows 桌面端调用系统注册的客户端协议，账号登录、拥有／共享资格、目录选择、确认及下载安装由对应客户端处理。成功发送请求只提示已请求打开安装界面，不宣称下载已开始或安装完成。安装请求不创建游玩会话、不记录时长，也不自动最小化；请求期间防止重复点击，正在启动／运行的游戏及应用更新／恢复维护期间拒绝安装请求。客户端未安装或链接关联异常时提示错误并恢复入口。浏览器预览不调用真实客户端。

新增后端 `install_game` 命令，需要包含此命令的新桌面进程；真实 Steam／Epic 安装界面与客户端行为仍需 Windows 验收。

本机定位仅针对 Windows 实现；普通浏览器显示明确标注的示例安装状态。测试覆盖真实格式的多游戏库清单、安装未完成、卸载与重新安装、目录缺失、清单损坏、离线库和启动前缓存过期。真实 Windows 注册表定位和 Steam 客户端交互需在目标设备实测。

### 在线详情与网盘下载信息

在线详情沿用现有主题、字体和按钮，用紧凑的封面与资料摘要展示名称、版本说明和分类，下载资源集中放在游戏资料之前。「下载资源」可直接定位到下载区；返回搜索结果保留输入草稿、筛选、列表位置与焦点。正文只解析文字及图片，不嵌入或执行原站 HTML、脚本、表单、广告或评论。

下载区展示已识别的网盘分享地址、提取码、原站文件密码和解压密码，支持复制、打开网盘和扫码。二维码由固定版本 `qrcode-generator` 在本机根据原始分享链接生成，不向第三方二维码服务发送链接。当前地址识别支持百度、夸克、迅雷、UC、阿里、Gofile 与天翼的 HTTPS 分享路径；只从对应文章正文提取，不把导航广告或其他文章的分享链接混入。

网盘入口采用单选切换，当前网盘的分享链接、提取码、打开按钮和二维码同步显示，不纵向重复堆叠全部二维码。可用方向键切换网盘，刷新后原分享链接仍存在时保留选择，刷新按钮也恢复键盘焦点；密码集中为紧凑字段。二维码采用本地生成的 SVG 直接呈现，保持白底，缩放、亮暗切换及离开页面后返回均可查看，不依赖原站二维码图片。

正文里的纯文本分享地址同样会识别，例如《尘埃异变 GRIME》下载页的「链接: https://…」与下一段「提取码: …」。解析保留相邻提取码，处理中文标点、重复链接及连续地址，不从脚本或表单文本中提取；OneDrive、Gofile 等需原站特殊获取的说明继续显示，不虚构对应下载地址。

原站新下载卡片使用 QRServer 图片时，也会从下载区二维码图片地址的 `data` 参数读取原始分享链接，例如《007 初露锋芒》的百度／夸克二维码。此过程只解析图片地址，不下载二维码、不向 QRServer 请求或提交链接；解出的地址仍须通过 HTTPS 网盘分享校验，并与普通链接去重。独立提取码优先读取对应卡片的提取码字段，避免被其他按钮文字干扰。

详情的「立即下载」入口如指向 `/go?post_id=文章编号`，只跟随已核对的 `520.gamers520.com`／`vip.gamers520.com` 数字文章地址，不执行跳转脚本。原站资源页需要访问密码时，仅使用游戏主站公开的文件密码提交原站 WordPress 访问表单；本次站点响应凭据只在内存中用于同域读取，不持久化或返回前端。不读取用户浏览器 Cookies，不登录用户网盘账号，不保存资源或启动下载。

下载信息获取失败或原站提供其他下载方式时，保留已读取正文，提供刷新与「打开原站下载页」；无法读取的地址不猜测、不补造。浏览器预览的二维码和链接明确为示例，不代表真实资源。2026-10-12 使用实际 Rust 客户端验证《空洞骑士》详情读取到 46 段正文／图片及百度、夸克、迅雷、UC 四项分享；Windows、系统浏览器打开与真实手机扫码仍需实机验证。

## 综合统计

侧栏「游戏统计」打开统计页，大屏顶部也提供入口。界面支持亮暗主题、触控与手柄，展示累计总览、每日趋势、活动日历、时长排行、成就进度、全成就游戏、平台分布和分页游玩记录。

统计页以本期游玩为首屏重点，集中展示时长、活跃天数、游玩次数、平均单次和新增成就；累计时长、成就概览与游戏库组成紧凑总览。趋势、日历、常玩游戏、成就进度与记录使用低对比表面和细边框分区，继承应用字体、主题色与亮暗模式；统计口径说明集中在底部可展开区域，后台刷新保留展开状态。本期指标与趋势合为首屏游玩区域，常玩游戏以封面陈列展示；趋势折叠记录启用前的历史区间，并明确显示开始记录的日期，不补算历史数据。普通页面和大屏统计均不限制内容最大宽度，窄窗口按内容切换列数。应用默认以最大化窗口启动，保留 Windows 任务栏和开始菜单的正常访问；标题栏的「还原窗口」可以恢复普通窗口，大屏模式仍自动全屏。

- 按全部／Steam／Epic／本地筛选，周期可选近 7／30／90／365 天或全部，默认近 30 天。累计总览只受平台筛选影响；活动指标、趋势与记录使用所选周期。
- Steam 官方累计时长与本机累计分别展示，不相加。时长排行可以查看本期本机、本机累计或 Steam 累计；缺失的官方时长显示未获取，缓存会标注。
- 逐日时长从新版首次运行开始保存，不估算或回填旧会话。启用之前的日期显示斜纹“未记录”，启用后的零活动日期显示零值。旧累计时长和会话仍保留，可选择“全部记录”查看。
- 每日记录复用游戏进程与清醒计时，跨午夜分日、休眠不补算；检查点和逐日累计在同一事务保存，重复写入不重复计时。正常退出与重启恢复会继续记录，启动器停止期间无法确认的时长不补算。
- 新增解锁统计排除首次历史导入、手动记录和测试弹层。Steam／Epic 官方同步建立基线后，只记录新增且实际解锁时间晚于统计启用时间的条目；趋势日期为启动器确认新事件的本地日期，官方同步可能有延迟。
- 成就按实际成就平台匹配。只有完整、非空的定义参与完成度与全成就判断；部分定义、尚未获取、暂无成就分别显示。手动记录计入当前进度并标注，不计入自动新增解锁趋势。
- 日历可按月翻页，点击日期查看当天时长、会话与解锁。日期详情中的会话时长是整次会话累计，与跨日拆分后的当天时长不同。排行榜和记录可进入游戏详情，返回时恢复统计筛选、滚动与焦点。
- 大屏方向键／摇杆移动，A 确认，B 返回，统计页 LB／RB 切换周期。统计自动请求最多每 5 秒一次，失败保留已显示的数据并提供重试；后台不主动获取焦点。

统计聚合、记录和界面分模块实现，不增加图表依赖。SQLite 新增逐日时长表和新解锁事件表，移除本地游戏时同时清理该游戏统计；不会移除游戏文件。

统计查询在后台使用独立只读连接和一致性快照，不占用窗口线程或游戏库共享连接；成就进度直接聚合数量。云同步队列按资源建立待处理记录索引，避免历史记录增长后逐款扫描整张表。快速返回复用五秒内的统计，离开页面后不再执行排队刷新，迟到结果不重绘其他页面。

### 数据备份与迁移

「设置 → 数据与迁移」提供创建备份、选择备份、路径预览和完整恢复。备份文件为 `.youji-backup`，包含游戏条目、收藏、本机累计与会话／每日统计、成就定义和解锁／统计事件、平台关联、个人 Steam 时长缓存、外观和行为选项、当前引用的封面与横幅。不包含影视库、游戏程序、游戏存档、字体文件、API Key、登录 token、Cookies、进程恢复记录或捕获控制文件；目标电脑的网络代理不随备份迁移。

游戏运行时可以创建备份：先保存当前计时检查点，再从一致性数据库事务导出白名单数据；未结束会话只在备份副本中结束，不停止游戏或修改原会话。缺失的封面列入摘要并跳过；归档先写临时文件、校验成功再原子提交，进行中可取消。首次备份使用本机日期时间命名，文件位置由保存对话框选择。

恢复先检查文件与 SHA-256 清单，再显示备份和目标数据数量。目录映射如 `E:/Games → D:/Games` 保留相对路径，按 Windows 大小写和目录边界匹配，不把 `Games2` 当作 `Games`；缺失游戏程序、启动器程序／自定义记录可逐款选择，也可暂时跳过。启动器路径随游戏一并备份和重定位。确认「恢复并重启」前需退出游戏、停止影视播放并等待捕获组件停止；应用会先在本机应用数据的 `safety-backups/` 保存现有数据，保存失败不会继续恢复。

确认后应用进入维护状态并自动重启。待恢复任务在新进程启动后台同步之前执行，以事务替换游戏记录；影视库及观看记录保持原样。封面使用新文件名，原缓存不覆盖；不会恢复旧进程或补发历史成就通知。游戏账号需要重新连接。字体缺失时按备份字体序列回退；仍缺失的游戏程序可在详情中编辑。设置页保留最近恢复结果和安全备份位置。

影视库暂不参与备份与恢复。备份格式版本为 3，保留游戏数据、整理与可迁移云身份；不读取开发期 v4 影视备份。不加密、不合并两份库、不做旧数据库迁移或定期备份。拒绝不支持的版本、未知文件、重复条目、越界路径、链接、错误校验值与非法记录；解压总量限 10 GiB，100,000 条目，数据 JSON 限 256 MiB，单张封面限 20 MiB。文件格式与故障处理约定见 `BACKUP-FORMAT.md`。

### Steam 家庭游戏库

进入「设置 → 游戏库与账号 → Steam 家庭游戏库」，点击「登录 Steam 家庭库」。游迹会打开独立的 Steam 官方登录窗口，在 Steam 页面扫码或完成账号与 Steam Guard 验证；应用不读取或保存密码。登录完成后保存本机家庭库查询凭证，SteamID64 未填写时自动填入当前账号；已填写时必须与登录账号一致。API Key 仍供个人成就与官方累计时长使用，家庭库导入本身使用网页登录授权。

点击「导入家庭游戏」读取完整可共享清单，包含尚未安装的游戏。按 AppID 与已有 Steam 条目合并，保留封面、路径、收藏、成就和本机记录；本人拥有的游戏归为自有，借用的游戏标注「Steam · 家庭共享」。侧栏收藏分组新增「家庭共享」，大屏模式在收藏视图中提供同样的筛选，Steam 平台分类仍包含全部 Steam 游戏。统计页单独显示 Steam 自有和共享数量。

重新导入时，只有成功取得有效家庭库快照才更新共享资格；不可共享内容跳过，原共享游戏若不再可用会标记「共享已失效」并禁用再次启动，历史记录和缓存保留。购买原共享游戏后，个人游戏库同步确认拥有即可转为自有。商店名称与封面刷新保留家庭共享标记，家庭成员的游玩时长不会导入为本人的时长；Steam 未返回个人官方时长时显示未获取。本机计时沿用现有独立记录。

Steam 自有时长与家庭库本人时长共用同步入口：启动立即尝试，后台每 5 分钟刷新，检测到 Steam 游戏正常结束、修改并保存 Steam 连接或在任一 Steam 游戏详情点击「更新资料」时也刷新。设置中可点击「同步本人时长」，同样更新两类时长，并显示家庭库本人时长结果；导入对应游戏库时直接保存此次返回的时长，不额外重复请求。同步进行中不重复发起请求，两类接口独立执行，家庭库未连接、授权过期、账号不匹配或未加入家庭时跳过家庭查询；一侧失败不影响另一侧保存成功结果。

家庭库读取 `GetSharedLibraryApps` 指定当前账号后返回的 `rt_playtime`，单位为分钟，转为秒存入按当前 SteamID 分开的独立缓存；常规个人游戏库有已知时长时优先使用，共享游戏缺失时显示「Steam 本人时长」。常规拥有库同步不会清空共享时长，失败保留历史值并标注缓存，字段缺失不写成零。本机累计继续独立计时，不与 Steam 时长相加。

不使用 `GetPlaytimeSummary.entries` 或 `entries_by_owner` 作为个人累计时长。实机查询中该家庭使用摘要的数值与个人库计数不一致；个人 `rt_playtime` 已用同账号 70 款有时长的自有游戏与 `GetOwnedGames` 交叉核对，均与个人分钟数一致。该数据与本机计时分别统计，不将家人的记录或拥有者汇总相加。

共享资格和可用副本最终由 Steam 客户端确认，安装检测与启动继续使用现有 Steam 流程。登录凭证过期后重新登录；断开连接清除游迹保存的家庭库凭证，已导入条目保留。登录窗口沿用当前启动时的 WebView 代理配置，修改代理后按设置页提示重启应用。此功能包含新增后端命令，需要重新启动开发桌面进程后生效。

实现拆分为 `src-tauri/src/steam_family/` 下的接口、登录、凭证、清单解析与持久化模块，使用现有 SQLite 设置表，不增加数据库迁移。远程 Steam 登录窗口未加入应用 IPC 权限；原生窗口导航通过随机 nonce 交接登录结果，登录凭证经 Steam 接口验证后才保存，不返回给主界面或输出到日志。导入身份不一致、列表不完整或请求失败时保留当前数据。

### 网络与代理

资料接口的跟随系统模式在每次请求前比较系统代理配置，变化时才重建共享客户端；配置未变则复用连接池，直连与自定义模式不执行系统配置检查。连接测试与当前配置一致时复用客户端，未保存草稿保持独立。

设置页支持资料接口和 WebView 图片跟随系统（默认）、不使用代理和自定义 HTTP／SOCKS5 代理。测试连接使用当前草稿，返回资料接口与图片域名的连通性；图片域名测试使用所选代理，不代表正在运行的 WebView 的图片加载结果。保存后立即替换 Steam、Epic、Xbox 资料请求的网络客户端；WebView 代理在窗口创建时设置，变更后需从托盘菜单完全退出并重新打开应用。设置页持续显示待重启提示，重复保存相同配置不会消除提示，恢复到本次启动配置后提示消除。配置保存在现有本机数据库中，代理失败不回退直连。

主窗口与成就提示窗口启动时使用同一已保存代理配置，共用原有 WebView 数据目录。游戏封面与横幅优先从应用本地缓存读取，缺失与主动更新时通过已有图片客户端下载；保存代理后新的封面下载立即使用新配置。成就图标、搜索结果与通知图片仍由 WebView 直接加载原地址，连接及缓存交给 WebView 和原站，其代理变更需要重启。保存代理不重载页面或成功图片。网络恢复时仅重试失败图片，保留已成功加载和正在加载的图片。


## 自定义标签与收藏夹

星标「我的收藏」保留为快速收藏；自定义收藏夹为平级手动清单，一款游戏可加入多个收藏夹和标签。侧栏「收藏夹」可折叠、创建及管理，显示完整成员数量；默认展示前四项，通过「查看全部」在侧栏直接展开全部，点击「收起更多」恢复前四项，当前选中的其他收藏夹额外显示，侧栏不设内嵌滚动；管理窗口支持重命名、删除和上移／下移。删除分类只清理归属，不删除游戏或记录。

游戏列表工具栏「标签」提供搜索、多选和全部／任意匹配，默认全部匹配；标签可与当前分类、收藏夹、名称和安装状态组合。详情页「整理」可编辑单款归属，新增分类立即保存、归属确认后保存。列表「批量整理」可全选当前结果，批量添加／移除标签、加入／移出收藏夹，保留未涉及的其他归属。改变分类或筛选时清空选择，后台刷新只移除已不存在的游戏。大屏模式可浏览收藏夹与筛选标签，创建和管理在普通模式完成。

普通模式的封面或列表行可拖到左侧收藏夹，松手后直接加入，保留原有收藏夹和标签归属。鼠标移动超过 8px 开始拖动，触屏长按约 450ms 后拖动；长按前滑动仍滚动页面。在批量整理模式下拖动已勾选游戏，会携带全部勾选游戏；拖动未勾选游戏只加入该款。目标收藏夹高亮，已存在的归属自动跳过；悬停「查看全部」或折叠的收藏夹标题约 550ms 自动展开，侧栏边缘可自动滚动，结束后恢复原展开与滚动状态。按 Esc、松手在目标外、失焦或切换页面取消，不触发卡片详情或收藏夹导航。侧栏收藏夹不可见的窄屏与大屏模式仍使用原有整理入口。

拖拽参考 Steam 的小封面预览：开始时原封面在约 240ms 内缩到指针旁，源卡片淡出；多选显示叠放封面与数量角标。预览复用源卡片已加载的图片，无封面或加载失败时显示游戏图标。收藏夹可见落点统一显示细虚线，悬停目标显示主题色填充、「＋」与松开加入提示；停留在展开入口时提示自动展开。触屏预览位于手指上方，减少遮挡；跟随指针不增加延迟，减少动态效果偏好下关闭入场动画。

普通模式下右键游戏封面、名称或列表行，打开游戏专用菜单；卡片不提供额外的三点按钮。菜单按常用操作、整理、管理及移除分组：启动／安装与详情入口、星标切换、可搜索并直接勾选归属的收藏夹子菜单、标签整理，以及更新资料和编辑／启动检测设置；本地游戏另有扫描记录、检测引导和需确认的「从游戏库移除」。收藏夹视图中的成员额外提供「从当前收藏夹移出」。Steam 操作遵循现有安装和家庭资格状态，Epic 保留客户端打开及独立安装入口，不推断安装状态；运行中等禁用入口显示原因。标签入口复用现有包含标签与收藏夹的整理弹窗。

批量整理时右键已勾选游戏，若包含多款有效游戏，则打开针对已选范围的加入／移出收藏夹、添加／移除标签菜单；右键未勾选游戏只针对自身，不改变选择。收藏夹勾选成功后菜单保持打开并刷新归属，失败保留原状态，重复操作在请求期间阻止。右键菜单支持方向键、Enter、Escape，可通过 ContextMenu 键或 Shift+F10 打开；键盘展开收藏夹子菜单时先聚焦搜索框，上下方向键在搜索框与菜单项间循环，搜索框中的 Home／End 保留文本编辑行为。子菜单靠近窗口边缘调整位置；切换筛选或页面、外部点击、页面滚动或失焦时收起。触屏保留长按拖拽，整理及管理可从游戏详情进入。输入框及已选文本保留原生复制菜单，其余普通页面默认图片菜单不再弹出。菜单只接入现有能力，未加入打开目录、商店、卸载或结束游戏操作。

分类独立于平台元数据保存，资料更新和重复导入不覆盖归属。无预置分类，支持全部游戏平台与家庭共享游戏。标签、收藏夹和可迁移云身份纳入 `.youji-backup` 的 v3 格式及安全备份；v1/v2 不兼容，新版会明确拒绝。需要 v1/v2 数据时应先用对应旧版恢复，再升级并创建新备份。


## 应用内更新

「设置 → 关于与更新」展示当前版本、本版与新版本的中文说明。Windows x64 NSIS 正式安装版默认启动后检查一次，可关闭；发现正式更新在设置入口显示圆点，下载与安装始终由用户触发。Mac 开发版和浏览器预览显示不支持应用内安装。

下载遵循应用代理配置，支持进度、取消和签名校验；离开设置页会继续下载。完整包保留在本机，重启后重新检查仍对应同一版本和签名时复用；离线或损坏的缓存不会直接安装。安装前要求游戏和捕获停止，保存计时检查点并协调维护状态，再启动简洁安装器并由安装器重启。更新不自动备份，也不会清除游戏库或账号连接。

签名发布、首次 Secrets 配置、更新缓存及 Windows 验收说明见 [UPDATING.md](UPDATING.md)。旧版需要先手动安装一次包含更新功能的正式版本。当前应用版本为 0.2.20。

## 游迹云账号与手动存档

设置新增「游迹云账号」，连接自行部署的 HTTPS 服务，通过受邀邮箱验证码登录。一个本地资料库绑定一个云账号，首次导入需预览并确认；其他设备连接相同账号后同步共享资料，本机程序路径、代理和平台凭据不上传。退出登录保留离线记录，重新登录同一账号后继续同步。服务端配置、邮件适配与私有存储要求见 [server/README.md](server/README.md)。

游戏整理按资源版本处理离线冲突，待同步修改保留在本机；采用云端或保留本机均需明确选择。游玩时长按唯一会话聚合，官方时长独立展示。绑定后移除游戏改为全设备归档，保留历史和存档，不删除游戏文件。

游戏详情新增手动存档档案，每个档案绑定一个专用目录。备份先保存本地快照，云上传失败仍可保留本地副本；恢复替换整个专用目录，先保存安全快照，并保留原目录和恢复日志。云端分叉需要选择，不根据上传时间自动覆盖。应用数据备份仍不包含游戏存档。

这是源码能力，需要重新构建 Windows 桌面端并配置云服务后才能使用；真实邮件、阿里云 OSS 与两台 Windows 设备需要环境验收。本次开发不自动部署服务或迁移用户数据。

云服务的容器配置见 [部署说明](server/deploy/README.md)。存档使用 OSS 原生接口，由独立 worker 校验后发布；文件上传完成不等于云端快照可恢复，详情页可点击「上传 / 查询状态」查询并继续上传后续快照。

导入预览按本机数据类别展示游戏、成就记录、游玩记录、收藏夹、标签及归属、成就资料、历史时长、官方时长、成就统计事件和平台账号数量。成就资料与时长注明覆盖的游戏数，避免将底层同步记录误认为游戏数；该摘要不是服务端最终新增数量。自动处理的游戏默认折叠，明细仅显示名称、平台与新增／关联状态，不展示内部 ID。未关联且有兼容候选的本地游戏单独提示核对，冲突仍需显式选择并重新预览后才能确认；预览本身不执行绑定导入。


## 游戏存档自动备份与确认恢复

在游戏详情的「游戏存档」绑定专用目录时，可选择「退出游戏后自动备份」与「自动上传云端并清理过期版本」。已有档案默认关闭，可从「自动备份设置」开启。自动上传须先登录、绑定资料账号并关联该游戏的云存档档案。

- 游迹运行或驻留托盘期间，已开始的游戏会话结束后排队；所有游戏和捕获任务停止后，每 2 秒检查文件列表、大小和修改时间，连续 3 次一致后采集。60 秒仍不稳定延后重试。内容未变化不新增快照，空目录须手动确认。完全退出游迹后暂停，启动时恢复队列并检查已开启目录。
- 压缩与内容校验在后台执行，本地快照成功落盘后才上传。上传任务和云端任务标识持久化，排队校验会自动查询；父快照发布后再传子快照。网络重试间隔为 5、15、60、300 秒；登录、配额、权限、校验等问题暂停，并在存档页面提供「重新尝试」。手动上传也会继续查询云端校验结果。
- 同机启动游戏读取本地目录。关联云档案或启动前发现不同云端来源时提供使用本地、恢复云端、查看历史；断网允许本地继续。恢复须二次确认，等待游戏停止，核对预览摘要，先备份当前目录再替换及校验；内容已变化则要求重新预览。恢复成功会更新内容基线，避免重复上传恢复内容。未完成的目录替换通过原有恢复日志在启动时回滚或完成。
- 云端目录规则只记录 Windows Known Folder、游戏安装目录或可靠 Steam 用户目录下的相对位置，不保存旧电脑的完整路径。Documents 使用系统 Known Folder API，支持重定向。候选目录须用户确认，多候选不自动取第一个；自定义目录或缺失目录需手动选择。没有联网目录百科或全盘扫描。
- 本地自动备份及明确开启的云端保留策略：最近 10 份与近 7 天每天最后一份取并集（UTC 分桶）。当前来源、分叉末端、待上传引用和手动保留版本受保护；自动上传模式的未上传快照不清理。每个档案的恢复安全 ZIP 另留最近 3 份，未完成恢复保护；原目录仍保留供人工核查。
- 清理只回收归档文件，版本元数据及父子关系保留；云历史标记「归档已清理，不可恢复」。延迟回收对象在实际删除前仍计入空间。旧客户端没有清理入口，常规上传不隐式触发新策略。

服务端需先应用迁移 `0005_save_automation.sql` 并部署新接口，再更新客户端。新增接口：档案 `settings` / `prune`、快照 `pin`；历史包含 `available` 和 `pinned`。本机自动化数据保存在存档库新增表中，不改变游戏库导入流程。
