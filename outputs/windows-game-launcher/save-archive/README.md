# 游迹存档归档与本地恢复

此 crate 供桌面端与服务端共用校验规则。create、verify、extract、file_hash 返回 Result；manifest_hash 始终调用 youji_cloud_protocol::digest，不对结构体直接序列化后的字节求摘要。

格式为 ZIP 中唯一的 manifest.json 与 files/<相对路径>。清单使用协议的 Manifest。仅保存普通文件，不保存空目录、ACL、文件时间或备用数据流；拒绝链接、重解析点、Windows 保留名、路径穿越、大小写与文件/目录冲突、额外条目、重复条目、加密条目和错误内容哈希。归档与未压缩内容均限制 2 GiB，最多 50,000 文件。

创建在源目录外暂存，对源目录前后扫描及归档实际内容三方比较，失败最多重试三次。解压只允许新目录，校验失败不修改已有目标。http 可选特性提供流式 HTTPS 对象传输，不跟随重定向，不将签名 URL 放入错误消息；服务端可不启用该特性。

## 桌面集成

- src-tauri/src/saves/ 使用应用数据下 saves/saves.sqlite 管理本机档案、快照和恢复日志；不改动主库结构。通过主库 sync_game_links(local_id,cloud_id) 只读取得共享游戏身份。
- saves::startup 在运行时和界面启动前恢复未完成操作。无法确认恢复状态则中止启动，保留原目录、暂存目录和日志。
- 备份/恢复复用全局 maintenance + operation_gate 与既有运行/捕获检查，当前会阻止所有游戏启动，而非仅此游戏。
- 恢复先提取到同卷相邻暂存目录，创建本地安全快照，持久化日志，重命名保留原目录，再安装完整新目录。异常立即尝试回滚，失败保持维护状态；下次启动继续恢复。
- 安全快照、回滚目录和故障暂存内容不自动清理。所有测试均使用临时目录。
- 云连接/上传/下载/历史/分叉选择/删除经既有认证接口；大对象请求单独流式传输。
- 上传按本地创建顺序重试。发起请求前冻结并保存版本，响应丢失时先按快照 ID 和双哈希检查云端历史。只在直接父版本仍是云端选定版本时为尚未发送的快照承接该 revision。
- 从不因查看云端最新版本改变本机父版本。下载与恢复、云端分叉选择是不同操作。
- 详情页入口为“游戏存档”。绑定、备份、恢复、分叉选择与删除均有明确界面；错误留在弹窗中，上传失败保留本地快照。
- 首版上传由用户点击“上传待传快照”，本地备份不自动发起网络请求。

## 验证

运行 cargo test --manifest-path save-archive/Cargo.toml --features http。tests/recovery.rs 直接加载实际客户端 store/restore 模块，验证恢复中断、校验失败回滚与安全备份失败等场景。Windows 重解析点检查由 Windows 文件属性实现，仍需 Windows 实机验证。没有对真实用户存档运行恢复。

正式端到端验收需要部署后的 HTTPS 云服务与私有加密对象存储。仅离线测试通过不能宣称远程上传及 Windows 文件锁已验收。

### 本轮验证结果

2026-10-21：包含 http 特性的 crate 编译成功，7 项归档/路径/规范摘要/签名长度测试与 7 项实际客户端恢复故障测试全部通过。独立测试加载 store.rs 产生 4 项未使用函数警告，无编译错误。前端生产构建及 detail-saves.js 语法检查通过。完整桌面构建由并行任务统一验证，本模块未重复启动桌面编译。

服务端已统一使用协议 digest，并支持同快照 ID 对过期上传重新申请任务。客户端逐项发送上传签名头；Content-Length 有且只有一份，且必须匹配本地 ZIP 实际大小。
