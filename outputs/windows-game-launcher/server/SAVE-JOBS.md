# 存档后台校验

API 和 worker 是独立进程，共用 Postgres 和私有 OSS。API 不启动校验循环；运行 `youji-cloud-server worker` 才会消费任务。数据库需先显式执行迁移。

## 客户端协议

1. `POST /v1/save-uploads` 申请任务。`uploading` 响应含 `uploadId`、`uploadUrl`、`headers`；客户端按返回的请求头直接上传 OSS。
2. `POST /v1/save-uploads/{id}/complete` 只持久化入队，返回 HTTP 202 和 `queued`/`validating` 状态，不等待下载、ZIP 或哈希校验。
3. `GET /v1/save-uploads/{id}` 查询 `uploading`、`queued`、`validating`、`completed`、`failed` 或 `expired`，以及 `attempts`、不含底层凭据的 `error`。
4. `completed` 才表示快照索引已发布，可以在历史中下载。重复 complete 返回 HTTP 200，不重复发布。已删除的快照不会因重放 complete 而重新创建。

任务只对创建它的账号和设备开放。重复申请同一快照必须保持请求内容相同；排队或校验中直接返回任务状态，不重新签发上传地址。失败后再次申请代表显式重试，过期后重新预留空间并签发新任务。

桌面端点击「上传 / 查询状态」即可续接；父快照完成前不上传依赖它的后续快照。本地归档始终保留，任务排队不阻塞后续离线使用。

## 调度与故障恢复

- 每个 worker 进程默认并发 2，可用 `YOUJI_SAVE_WORKERS` 配置 1–8。部署多个 worker 时应按总并发预留 CPU、磁盘和数据库连接。
- 领取任务使用短事务和租约；每 30 秒续租，租约 2 分钟。心跳与校验独立推进，续租请求最多等待 15 秒。
- 瞬时错误 30 秒后重试，最多尝试 3 次；进程中断后重新领取也计入次数。明确损坏或不合法的归档直接失败。
- 每次尝试使用独立最终对象键及租约令牌。失去租约的任务不能发布索引或修改新任务结果。
- 单次异步任务时限 45 分钟。Rust 阻塞校验不能强行中断，因此并发许可和临时目录由实际阻塞任务持有至结束，取消不会放大校验并发。
- `YOUJI_SAVE_WORK_DIR` 默认系统临时目录下的 `youji-save-jobs`；容器中为持久工作卷。仅清理本组件创建、超过 24 小时的临时目录，不清理用户历史存档。

`/health` 只检查 API 存活。正式环境还需监控最老排队时间、`failed` 数量、配额占用、工作卷剩余空间及 worker 进程；API 可用不代表 worker 正在消费。


## OSS 容量预留与清理

`USER_QUOTA_BYTES` 按“`save_objects.bytes` + `save_object_gc.bytes`”计算当前账号占用，不再仅统计已完成快照或未过期上传。申请、领取和发布统一先锁用户，再锁上传任务，同用户容量变更串行处理。

- 申请上传时为暂存键预留声明大小；每次 worker 尝试再为独立发布键预留相同大小。因此新内容在暂存与发布并存时需要两份容量。
- 失败、任务过期、重置重试次数、失去租约，都不会释放旧尝试预留。配额不足时尝试会失败，需等待清理或删除不再需要的历史并等待物理回收。
- 正式对象发布时，在同一事务中插入对象并移除相应 GC 预留，容量只转账一次。
- 校验后先按账号内内容查重，已存在内容不再上传完整副本。确定此次尝试从未写入 OSS 时可以释放其空发布预留，暂存对象仍计入配额。
- 若并发尝试已经写出额外副本，该副本继续占用预留，直到 GC 成功删除。删除历史索引也只是把正式对象容量转入 GC，不能提前释放。
- 暂存与尝试键通常至少保留 25 小时；历史对象延后至少 15 分钟回收。小时级清理会进一步延迟释放。OSS 删除失败或数据库清理事务失败均保留容量记录，可安全重试。
- 新迁移保留既有迁移校验，旧 GC 记录按对象键中的账号回填；无法还原大小的旧孤立尝试按单对象上限 2 GiB 保守预留，清理后释放。

这是应用管理的对象键容量账本，不是 OSS 账单统计。版本控制保留的历史 versionId、桶中人工写入对象等不在账本内；建议使用专用、从未启用版本控制的桶，详见 [OSS 配置](OSS.md)。
